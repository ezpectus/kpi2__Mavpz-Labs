# Task: Lab 2 - Вимоги та Use Cases (EARS + user stories + Gherkin)

## Мета

Структуровані вимоги, сценарії використання і трасування.

## Артефакт

EARS-вимоги (WHEN <тригер>, система SHALL <реакція> / WHILE <стан>, ...) + user stories + Gherkin-сценарії (Given/When/Then); матриця трасування "вимога-id <-> сценарій/UC" як таблиця в Markdown. Рендер - Use Case Diagram (PlantUML / Mermaid) з >=2 типами акторів, include/extend, узагальненням.

## Що зробити

- spec.md: >=2 типи акторів (людина + зовнішня система/сервіс), головні цілі
- Написати EARS-вимоги, user stories, Gherkin; побудувати use-case-діаграму
- Матриця трасування: зв'язки багато-до-багатьох (не 1:1); позначити непокриті вимоги/UC
- Аудит: EARS на двозначність; include/extend; звірити акторів і сутності з моделлю даних (Завдання 1); топ-3 розбіжності
- DEFENSE.md: чому такі межі сценаріїв

## Ознаки відмінного виконання

- Вимоги в EARS однозначні й тестовані
- Трасування реально багато-до-багатьох
- Узгодженість з моделлю даних
- Є >=1 непокрита вимога з поясненням
