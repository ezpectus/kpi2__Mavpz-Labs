# DEFENSE: Lab 2 - Use Cases

## 1. Намір і критерії

Описав вимоги до VideoHub: EARS-вимоги, user stories, Gherkin-сценарії, use-case-діаграма, матриця трасування M:N. Критерії в spec.md - >=2 типи акторів (людина + зовнішня система), include/extend і узагальнення на діаграмі, узагальнення дитина -> батько, UC асоційовані з актором що їх виконує, >=1 непокрита вимога з поясненням, узгодженість з ER-моделлю Lab 1.

Межі сценаріїв: UC = ціль актора з обчислюваним результатом, не крок UI. Тому UC9 Authenticate - окремий спільний сценарій (див. ADR-003), а операції типу "delete comment" - всередині UC5 (без функціональної декомпозиції).

## 2. Топ-3 розбіжності (spec <-> артефакт) + коміт-виправлення

- **Не було зовнішнього актора** - проти критерію ">=2 типи акторів (людина + зовнішня система)". Вимога REQ2 каже про Google OAuth, а на діаграмі його не було. Додав Google OAuth + generalization. Коміт-модель: `5ee5cb1`; критерій у spec уточнено `fdba085`
- **Не було include/extend та узагальнення** - проти критерію "діаграма з include/extend та узагальненням". Додав UC9 Authenticate (include для UC2/3/5/6/7) і UC8 --|extend|> UC4. Коміт-модель: `d7dad19`; критерій про напрямок generalization уточнено `fdba085`
- **Узагальнення у зворотньому напрямку в .mmd + Register/Login на User** - .mmd показував "Guest різновид User" (суперечило .drawio!), а реєстрацію/логін виконував User, хоча реєструється саме Guest. Критерію в spec не було - додано "узагальнення дитина -> батько" і "UC з актором що виконує". Коміт spec+модель: `fdba085`

Повний список - AUDIT.md (6 розбіжностей, вкл. матрицю трасування 1:1 -> `c9cee4e`).

## 3. Ключове рішення (ADR)

**Authenticate - окремий include-UC чи крок усередині сценаріїв.** Зважив: precondition (приховує сценарій, немає трасування), inline-крок у кожному UC (дублікація в 5 місцях), окремий UC9 з include (одна точка зміни, узгоджено з Lab 3 де UC9 = AuthService.validateToken). Обрав UC9. Деталі: `adr/adr-003-authenticate-include-uc.md`.

Окремо формат: канонічний source діаграми - PlantUML `usecase.puml` (Mermaid не має UC-нотації: актори=круги, UC=прямокутники, без boundary - це було файндінгом №5). .drawio синхронний семантично; рендер - renders/usecase.png.

## 4. Перевірка узгодженості з попередньою моделлю (Lab 1)

Порівняв кожну сутність ER-моделі з use cases:

- User -> актори Guest/User (реєстрація створює User entity; UC1/UC2 на Guest, бо User ще не існує)
- Video -> UC3 Upload, UC4 Watch
- Comment -> UC5 Comment
- Like -> UC6 Like
- Subscription -> UC7 Subscribe
- googleId в User -> актор Google OAuth (поле nullable саме через OAuth - LAB 1 узгоджено)

Кожна сутність покрита хоча б одним UC, кожен UC спирається на сутність з Lab 1.
