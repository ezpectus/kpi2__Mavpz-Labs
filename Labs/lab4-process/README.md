# Lab 4 - Process: VideoHub

## Домен

VideoHub - платформа для завантаження та перегляду відео (YouTube-клон).

Реалізація: [github.com/ezpectus/VideoHub](https://github.com/ezpectus/VideoHub)

## Обраний процес

**UC3: Upload Video** (з Завдання 2) — той самий процес що деталізовано в Lab 3 (Sequence), але інший ракурс:

- Lab 3 (Sequence): взаємодія компонентів у часі — хто кого викликає
- Lab 4 (Activity): потік робіт процесу — кроки, розгалуження, паралельні гілки, ролі

## Форма: Activity-діаграма

Обрано activity (не машину станів), бо UC3 — процес з чітким початком (форму) і кінцем (201 або помилка). Машина станів краще підходить для життєвого циклу об'єкта (Video: draft -> published -> archived) — це інша задача. Обґрунтування: `adr/adr-004-activity-vs-statemachine.md`.

## Зв'язок з попередніми лабами

- **Lab 1 (ER):** Video створюється з authorId = userId
- **Lab 2 (UC):** деталізує UC3; auth = include UC9
- **Lab 3 (Sequence):** той самий процес — гілки помилок звіряються в аудиті

## Структура

- `task.md` - умова
- `spec.md` - намір, кроки, ролі, розгалуження, критерії
- `model/` - source діаграми
- `renders/activity.png` - рендер
- `AUDIT.md` - розбіжності spec <-> артефакт + коміти-виправлення
- `DEFENSE.md` - точка входу для рев'ю
- `adr/` - ADR-004 (форма моделі) + наступні
- `ai/` - слід AI-ітерації (промпти, аудит, workflow)
